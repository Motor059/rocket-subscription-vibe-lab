# [Day 5] 프론트엔드 Case A (명세 부재) 바이브 코딩 및 유지보수 결함 로그

## 1. 실험 개요
- **일시:** 2026년 5월 23일
- **목적:** 프론트엔드 개발 시 화면 상태 명세(State Specification) 및 컴포넌트 아키텍처 설계 없이 AI에게 바이브 코딩을 지시했을 때 발생하는 기술 부채와 컨텍스트 누적으로 인한 유지보수 비용 폭발을 정량적으로 관찰 및 기록한다.

## 2. 입력 프롬프트 요약
```text
<1회차>
(백엔드 코드 파일 첨부)
현재 백엔드 코드 구성이 이런 상태야. 자세하게 분석해주고, 구독 탐지 결과를 보여주는 프론트엔드 화면을 React와 Tailwind CSS로 구현해 줘.
```
```text
<2회차>
FSM 동기화, API 메서드 동기화, 4대 상태 처리, 날짜 포맷 파싱 및 탐지 트리거에 대한 피드백을 참고해서 다시 코드를 수정해서 작성해줘.
```

## 3. 토큰 누적 비용 분석 (Context Accumulation)
- **1회차 초안 생성 비용:** 약 1,500 토큰
- **2회차 디버깅(유지보수) 누적 비용:** 약 4,650 토큰 초과 (초안 대비 약 2배 폭발)
- **정량적 관찰 결과:** 사전에 엄격한 제약 조건을 주지 않아 발생한 표면적 결함들을 대화로 해결하려다 보니, 기존의 불완전한 코드 전체와 7가지 요구사항이 단일 컨텍스트에 누적되어 재입력됨. 프론트엔드 영역에서도 사전 설계 부재가 기하급수적인 연산 비용(토큰 낭비)으로 이어진다는 프로세스 미적용의 한계를 명확히 입증함.

## 4. 관찰된 치명적 결함 및 유지보수 한계 (기술 부채 요약)

###  결함
1. **FSM(유한 상태 기계) 무력화:** 백엔드 도메인 아키텍처에서 무결성을 검증하는 방어 로직을 무시하고, 프론트엔드가 서버 응답 확인 없이 임의로 상태를 `CANCELED` 및 `IGNORED`로 직접 결정 및 세팅하는 불일치 결함 발생.
2. **잘못된 상태 전이 및 동기화 부재:** 백엔드 API와의 실시간 상태 동기화가 이루어지지 않아, 해지 불가 상태임에도 UI 레벨에서 액션이 허용되는 비결정론적 워크플로우 유발.
3. **HTTP 메서드 오추정:** 명세서가 부재하여 백엔드에 설계된 `PATCH` 엔드포인트를 `POST` 메서드로 임의 추측하여 구현하는 통신 규격 불일치 결함 식별.
4. **4대 UI 상태(Loading/Error/Empty) 누락:** 서버 응답 지연 시 화면이 하얗게 멈추는 현상, 데이터가 0개일 때 공백 화면 노출, 서버 예외 발생 시 `alert()` 창 하나로 끝내는 안일한 에러 핸들링 등 기본적인 UX 상태 처리가 전무함.
5. **백엔드 응답 데이터 미활용:** 서버가 리턴하는 무결한 상태 메시지를 활용하지 않고 프론트의 로컬 State 값 변경에만 의존함.
6. **날짜 포맷 파싱 불일치:** `LocalDateTime` 파싱 로직의 부재로 인해 목업 데이터의 날짜가 과거(2023년)로 고정되는 데이터 표현 결함 식별.
7. **배치 탐지 트리거 누락:** 백엔드에 존재하는 수동 배치 트리거(`POST /api/v1/subscriptions/detect`)를 실행할 수 있는 관리자성 컴포넌트가 화면에서 완전히 누락됨.

### 유지보수 시뮬레이션의 근본적 한계: God Component의 고착화
피드백을 통해 표면적인 기능 오류(PATCH 변경, 로딩/에러 분기 처리 추가)는 억지로 패치(Patch)하는 데 성공했으나, 모든 상태 관리와 Fetch 로직, UI 스타일링 코드가 **`App.tsx` 단일 파일에 누적 집약되어 거대 컴포넌트(God Component)가 생성됨**. 
결과적으로 단일 책임 원칙(SRP)이 완전히 붕괴되어 재사용 및 레이어 분리가 불가능한 스파게티 기술 부채가 고착화됨.
