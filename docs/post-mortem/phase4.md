# [Phase 4 회고록] 시스템 구조 리팩토링 및 바이브 코딩 한계 분석 최종 회고 (Post-mortem)

## 1. 개요
본 회고록은 4차시(Day 13 ~ Day 16) 동안 진행된 시스템 결합도 완화를 위한 아키텍처 리팩토링과 프로젝트 전반에 걸친 AI 바이브 코딩의 뼈아픈 실패 분석, 그리고 이를 자산화한 5대 원칙 수립 과정을 기록한다.

## 2. 아키텍처 리팩토링 및 시스템 관측성 확보
AI가 산출한 코드는 기능적으로는 동작하지만, 장기적인 유지보수 관점에서는 심각한 구조적 부채를 내포하고 있었다. 이를 실무 수준으로 끌어올리기 위해 대대적인 리팩토링을 단행했다.

* **[Backend] 이벤트 기반(Event-Driven) 아키텍처 도입:** 초기 AI 코드는 구독 저장 로직과 외부 알림 서비스가 하나의 트랜잭션에 강하게 묶여 있었다. 알림 발송 실패 시 전체 데이터가 롤백되는 치명적 결합도를 끊어내기 위해, Spring의 `ApplicationEventPublisher`를 도입하여 비동기 이벤트 발행 구조로 완벽히 격리했다.
* **[Backend] 관측성(Observability) 확보:** AI는 시스템의 상태 변화를 스스로 기록할 줄 모른다. 이에 `Slf4j`를 활용하여 FSM 상태 전이(`DETECTED` ➔ `WARNING` 등)와 예외 방어 시점마다 상세 로그를 남기는 '관제탑'을 구축해 운영 안정성을 확보했다.
* **[Frontend] Custom Hook 분리:** React 역시 단일 파일(`App.tsx`)에 API 통신과 렌더링이 뒤섞여 있었다. 데이터 페칭과 비즈니스 로직을 `useSubscriptions` 커스텀 훅으로 추출하여 컴포넌트의 응집도를 극대화했다.

## 3. 포스트모템 (Post-mortem): 실패와 장애 딥다이브
성공한 기능보다, AI의 한계로 인해 처참하게 무너졌던 경험을 소프트웨어 공학적 관점에서 분석했다.

### 3.1. 기획의 파편화와 범위 변질 (Scope Creep)
* **현상 및 원인:** 초기 '오픈뱅킹 API 실 데이터 연동'을 무분별하게 지시했을 때, AI의 압도적인 코드 산출 속도는 엔지니어에게 "어떤 기능이든 쉽게 붙일 수 있다"는 환상을 주었다. 결국 인증 토큰 갱신, API Rate Limit 등 요구사항이 통제 없이 팽창하는 '범위 변질'로 이어졌다.
* **교훈:** 코드가 쏟아지는 속도가 빠를수록, 최소 기능 제품의 바운더리를 긋고 통제하는 '요구사항 공학' 역량이 성패를 가른다.

### 3.2. 에러 핑퐁과 막대한 토큰 누수 (Prompt Failure)
* **현상 및 원인:** 에러 로그 수십 줄을 그대로 복사해 땜질식 수정을 요구할 때마다, 다른 곳에서 에러가 터지며 컨텍스트 누적으로 인한 막대한 토큰 낭비가 발생했다.
* **교훈:** 에러 로그 대신에 인간이 명확한 의도를 담은 '실패하는 단위 테스트'를 주입했을 때 비로소 AI의 답변 범위가 통제되었고, 10회의 핑퐁이 1~2회로 줄어들며 전체 비용을 50% 이상 절감할 수 있었다.

### 3.3. 통합 환경의 나비효과 (E2E 버그 발견)
* **현상 및 원인:** 단위 테스트를 완벽히 통과했던 가맹점명 정규화 로직이 대소문자를 엄격히 구분하는 DB 영속성 계층과 결합하자 데이터를 찾지 못하는 치명적인 버그(Coupang vs COUPANG)를 일으켰다.
* **교훈:** AI는 파편화된 로직 최적화의 천재지만, DB-서버-UI가 맞물려 돌아가는 전체 시스템 통합 환경을 꿰뚫어 보는 시야는 없다. 통합 디버깅은 오직 인간 아키텍트의 고유 영역이다.

## 4. 최종 결론: 나만의 바이브 코딩 5대 원칙 선언
본 프로젝트의 정량적/정성적 데이터를 집대성하여, 다가오는 AI 시대에 엔지니어가 갖추어야 할 5대 원칙을 수립하며 프로젝트를 완수했다.

1. **제1원칙 (기획):** AI는 Coder일 뿐 시스템의 경계를 긋는 아키텍트는 인간이다.
2. **제2원칙 (프롬프트):** 가장 완벽하고 저렴한 프롬프트는 소프트웨어 설계 명세서다.
3. **제3원칙 (QA):** 테스트 주도 개발은 버그 픽스가 아니라 환각 통제 장치다.
4. **제4원칙 (UI/UX):** 프론트엔드의 화면은 백엔드의 도메인 상태가 지배해야 한다.
5. **제5원칙 (통합):** 통합 환경의 나비효과를 추적하는 직관은 대체 불가한 인간의 영역이다.
